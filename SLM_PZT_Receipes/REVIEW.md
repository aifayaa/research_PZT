# Slide-code review

This audit demonstrates that the slides in `pzt_slides.pdf` are supported by the code living inside this directory.

## Corpus & parsing (slides 5–7)
- Slide 5 describes the Hugging Face `corbt/all-recipes` dataset (2,147,248 entries, `input` field with Ingredients/Instructions). `download_dataset_json.py` reproduces that NDJSON format, and `pzt/parser.py` enforces the strict “Title / Ingredients / Instructions” layout called out on the slide. The parser also reports warnings for missing sections and normalizes ingredient/operation text exactly as shown in `docs/PZTpp_Algorithm.md`.

## Parts + embeddings (slide 6)
- `pzt/norm.py` computes ingredient heads, operation tokens, and TF–IDF weights. `pztpp/build.py` writes the head/op vocabularies, IDF numpy arrays, and postings referenced in the slide, while `pztpp/embeddings.py` builds SBERT (all-MiniLM-L6-v2) embeddings for ingredients/full/instructions, matching the “dense + structured” representation described on slide 6.

## Scoring & few-switch zone (slides 7–11)
- `pztpp/score.py`, together with `pztpp/run.py`, implements the edit cost (`miss_ingr`, `fa_ingr`, `switch_cost`, `edit_cost`) and zone filtering (`few_switches` vs `closest`) mentioned on slides 7–11. The CSV/JSONL schema written by `run.py` includes the fields listed in slide 8 (`scores`, `masses`, `explanations`, etc.), and the default `quality` preset reuses the hyperparameters (`cand_k≈500–1000`, `min_ingr_cov=0.55`, `a_m=0.55`, etc.) stated in the deck.

## Experiments & results (slides 9–12)
- Slides 9 and 10 report the “10K exact” experiment, the “percent proximal top-1”, and the median switch cost. These statistics are produced by:
  1. Building a 10K, no-ANN run with `pztpp_transfer.py build --no-ann --limit 10000`.
  2. Running `pztpp_transfer.py run ... --mode few_switches --cand-k 1500` to extract the same rankings plotted.
  3. Feeding the resulting run directory into `scripts/exp_compare_measures_10k.py`; that script enumerates full, ingredient, head, op, legacy MISS, and PZT++-Edit methods and writes the CSV/JSON files used to generate the bar charts on slides 10–11.
- Slide 12’s “few switches explanation” is generated by `scripts/generate_llm_adaptations.py`, which converts the missing/extra heads/ops into piecewise instructions. The same head/op vocabulary the slide refers to is persisted under `head_vocab.json`/`op_vocab.json` during the build step.

## Summary
- The developer-facing documents (`README.md`, `CODE_DOC.md`, `EXPERIMENTS.md`, `docs/PZTpp_Algorithm.md`) now explain how to reproduce the slides’ data, how the CLI and scoring modules generate the reported fields, and why the results are auditable.
